# 工程控制论与 Sentinel Harness：可参考映射

本文将钱学森《工程控制论》中的**系统抽象与工程判据**转写为 IDE / Agent / Sentinel 产品语言，供架构评审、Harness 演进与验收清单对照使用。不要求在实现层套用具体传递函数推导；**价值在于「稳定性、反馈、扰动、观测、裕量」等概念与当前系统的对齐方式**。

## 1. 思维模型：从装置到系统

| 维度 | 传统自动调节 | 工程控制论（抽象） | Sentinel 中的对应取向 |
|------|-------------|-------------------|------------------------|
| 研究对象 | 具体机械/电气装置 | 一般动力学系统（结构 + 行为） | Intent、DAG、Worker、验证门、物化路径视为**可观测闭环** |
| 核心关切 | 消静差、提精度 | 稳定性、可靠性、最优性（在约束下） | 验证门 / 漂移 / build 门禁 / feature `passes` 与**可证终态** |
| 手段 | 经验调参 | 可分析模型（微分方程、传递函数等） | Eval、trace、审计日志、成本账本、结构化验证包 |
| 对干扰 | 常视为「外部破坏」 | 统计特征 + 反馈对冲 | 模型误差、工具失败、网络空检索、用户改需求 → **降级、重试、熔断、回滚** |

**产品含义**：不默认「模型单次输出正确」，而默认**闭环**在统计意义上可约束；与 [产品信条：结果偏差即系统责任](./anthropic-harness-alignment.md#产品信条结果偏差即系统责任) 一致。

## 2. 内容演进路径 → 产品映射（提要）

- **A. 稳定性（线性基础）**  
  工程含义：小扰动下不发散。  
  **映射**：`strictVerification`、`verifyNpmBuildAfterImplement`、漂移检测与 `matchedSuccessCriteria` 链；避免「假完成」在闭环里被放大为正反馈。

- **B. 反馈与伺服**  
  工程含义：用闭环修正偏差，降低对「单点极致精密」的依赖。  
  **映射**：Verifier / 自动修复轮次、`behavioralE2E`、工具结果校验（如 `agentToolHarnessValidation`）；用架构补偿模型与工具的随机性。

- **C. 暂态与稳态性能**  
  工程含义：除稳定外，还要求响应速度与稳态误差界。  
  **映射**：节点粒度、自动修复上限、`softTokenBudgetTotal` 告警；避免无限振荡式改代码（需配置上限与人工介入点）。

- **D. 随机干扰与噪声**  
  工程含义：环境不可完全预测，用统计与滤波思路。  
  **映射**：检索 0 条、MCP 失败、LSP 抖动；**可观测 + 用户可见提示**（如 HGT-022），而非静默继续。

- **E. 非线性与最优（Bang-Bang 等）**  
  工程含义：开关/饱和等非线性带来不同相平面行为。  
  **映射**：blocked vs completed、staging promote、checkpoint 回滚等**离散决策**；需在文档与配置中写清切换条件。

## 3. 「幻觉」风险（控制论视角）→ 审核锚点

以下名称保留原书精神，在软件系统中作**类比验收项**（非要求画波特图）。

| 风险类型 | 含义 | 建议审核锚点（本仓库） |
|----------|------|------------------------|
| **模型失配** | 受控对象被过度简化，控制律在真实参数下失稳 | 变更 `allowedFiles`、依赖、脚手架假设后，是否仍跑通 [harness-eval](../../scripts/harness-eval/README.md)；`verifyNpmBuild`、漂移是否在边界场景仍合理 |
| **观测器误差** | 由测量推断状态时，测量被污染则「状态幻觉」 | CSO / 工具返回是否可追溯（trace、审计日志）；关键事实是否经磁盘或构建验证而非仅模型叙述 |
| **时延与相位滞后** | 决策链路过长，指令到达时已过时 | 长链路是否有取消/超时；自动修复与多轮工具是否有**上限**；是否需 worktree 隔离（HGT-005）降低耦合振荡 |

## 4. 人类评审提示（工程安全性）

在审阅基于 Agent 的交付方案时，除功能演示外，可主动索要或检查：

1. **失稳边界**：是否仅有 happy path 演示，还是包含阻塞路径、build 失败、验证门失败、回滚的记录或脚本。  
2. **裕量**：配置扰动（如关联网、关某 MCP、收紧 `strictVerification`）下系统是否**可降级**而非静默错误放大。  
3. **可追溯**：单次任务是否可从日志/trace/审计串联 LLM → 工具 → 内核（见 HGT-002 思路）。
