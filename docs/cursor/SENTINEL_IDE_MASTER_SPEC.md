# Sentinel-IDE Master Spec

## 文档定位

本文件不再承担“愿景宣言 + 工程契约 + 落地路线图”三种职责，而是作为 Sentinel-IDE 文档体系的总入口。

拆分后的目标是：

- 让高势能叙事保留想象力，但不污染近期工程约束
- 让工程规范只描述未来 6-12 个月内可执行、可验证、可拆分的能力
- 让路线图单独承担“优先级、阶段、依赖、里程碑”表达

---

## 文档结构

### 1. 愿景文档

文件：`vscode/docs/cursor/SENTINEL_IDE_VISION.md`

职责：

- 定义 Sentinel-IDE 的长期北极星
- 解释“意图中心”“代码即投影”“逻辑治理者”等核心叙事
- 描述终极阶段能力，例如软件自愈、意图级演化、基质无关合成

不应承载：

- 近期接口设计
- 数据结构细节
- 具体到服务级别的实现承诺

### 2. 工程规范

文件：`vscode/docs/cursor/SENTINEL_IDE_ENGINEERING_SPEC.md`

职责：

- 定义 V1 阶段内需要落地的系统对象、边界和服务职责
- 明确当前 `aiCore` 基座与后续增量演进关系
- 约束 `Intent Graph`、`Reasoning Trace`、`CSO`、`Task Graph`、验证闭环等核心对象的最小可实现形态

应重点回答：

- 现在已经有什么
- 接下来先做什么
- 每一项能力如何接入现有服务

### 3. 路线图文档

文件：`vscode/docs/cursor/SENTINEL_IDE_ROADMAP.md`

职责：

- 给出阶段拆分、优先级和依赖顺序
- 区分“已具备原型”“V1 必做”“V1.5 增强”“研究项”
- 管理预期，防止把研究能力误写成短期承诺

---

## 当前总判断

Sentinel-IDE 的总体方向仍然成立，但应以“分层表达”取代“单文档承载全部语义”。

其中：

- 长期成立的，是“从源码中心转向意图中心”的战略判断
- 中期成立的，是“Code Graph + LSP Feedback + Task Graph + Verification Loop”的工程骨架
- 短期可执行的，是围绕当前 `aiCore` 服务继续增强上下文注入、任务编排、检查点、测试闭环与代码图谱能力

---

## 一句话定义

**Sentinel-IDE 是一个以意图治理为长期目标、以工程闭环为近期落点、以分层文档体系管理复杂度的 AI 原生 IDE 计划。**
