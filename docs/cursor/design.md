# Sentinel-IDE 技术实现规范文档 (2026版)

> 构建从"概率代码生成"进化为"工程化逻辑合成"的开发环境。开发者不再是 AI 的保姆，而是**逻辑治理者 (Logic Governor)**。系统通过"实现-对抗-验证-路由"的闭环，确保在交付 100% 正确代码的同时，实现最优的 Token 投入产出比。

---

## 1. 第一阶段：混合动力引擎 (Rust Body + Python Brain)

**目标：** 建立毫秒级的全库感知能力，解决大型项目加载慢和 AST 分析不准的问题。

### 1.1 Rust 执行层（The Body）

- **Rust Sidecar 进程：** 集成 **Tree-sitter** 引擎，实现增量式 AST 解析，支持毫秒级的全库符号索引。
- **高性能文件 I/O：** 负责语义索引构建、大规模代码静态分析以及与 SMT 求解器（如 Z3）的底层通信。
- **LSP 诊断反馈流：** 将 IDE 原生的错误（Error）和警告（Warning）实时喂给 AI，形成"生成-验证-自修复"的闭环。

### 1.2 Python/LLM 决策层（The Brain）

- 负责高层级规划、意图解析、上下文编排及提示词管理。

### 1.3 神经符号网关（Neuro-Symbolic Gateway）

- 在 LLM 输出与代码执行之间插入符号逻辑层。所有生成的代码必须通过语法检查、类型检查和预定义的逻辑约束（Constraint Programming）。

### 1.4 失忆代理协议 (Amnesic Agent)

- 每一轮迭代强行重置上下文，仅由 Rust 层精确注入当前受影响文件的 AST 快照、`PROGRESS.log` 和 `SUCCESS_CRITERIA`，杜绝幻觉堆叠。
- 这种"上下文卫生"能有效防止幻觉堆叠并节省 Token。

---

## 2. 第二阶段：知识基座 (Code-GraphRAG & 领域知识库)

**目标：** 解决"不规范 PRD"问题，让 AI 拥有比开发者更深层的领域常识。

### 2.1 自动化领域图谱构建

- IDE 启动时自动扫描全库代码、历史 PR 记录、文档以及 `.cursorrules` 等配置文件，构建 **"领域知识图谱 (Ontology)"**。

### 2.2 语义对齐与意图对齐 (Semantic Alignment / Intent Refinement)

- 开发者输入模糊意图（如"实现登录"）时，系统从图谱中提取关联实体（如 `StripeAPI`、`OrderService`、`UserRiskLevel`）和隐含规范（如 JWT + Redis），自动补全缺失的非标需求。

### 2.3 持久化推理电路 (Reasoning Circuit)

- 存储不仅是代码，而是 **"意图轨迹"**。记录每一行代码修改背后的逻辑回路，确保后续 Agent 接手时不会丢失上下文。

---

## 3. 第三阶段：决策中枢 (成本感知的智能模型路由)

**目标：** 针对模型价格差异，实现任务的分级分派，最大化资源效率。

### 3.1 任务复杂度评分引擎 (TCE)

根据以下指标计算 **任务复杂度指数 (TCI)**：
- 受影响文件数量
- 循环复杂度
- 是否涉及数据库 / 安全协议
- 跨模块依赖深度

### 3.2 三层模型分派池 (Tiered Model Pool)

| 层级 | 模型示例 | 适用场景 |
|------|----------|----------|
| **Tier 1** (Fast/Cheap) | Claude Haiku / GPT-4o-mini | 文件操作、搜索、格式化及简单的单文件 Bug 修复 |
| **Tier 2** (Balanced) | Claude Sonnet | 标准功能开发、中等复杂度的多文件重构 |
| **Tier 3** (Reasoning/Power) | Claude Opus 4.6 / GPT-5 | 架构设计、高风险逻辑变更、复杂的死锁排查及对抗性审计 |

### 3.3 动态升级机制 (Escalation)

- 如果 Tier 1 尝试修复失败（验证未通过），系统自动将任务升级至 Tier 2/3 并携带失败日志，而非在低效模型上反复重试浪费 Token。

### 3.4 上下文状态对象 (CSO) 与 JIT 模式

- **CSO 压缩协议：** 使用专门的 LoRA 适配器（State-Tracker）将冗长的对话历史实时蒸馏为压缩的、结构化的 **"状态快照"**，将上下文增长率降低 10 至 25 倍。
- **即时工具加载（JIT Tool Schema）：** 不要一次性把所有工具（如 50 个 API 说明）塞进 Prompt。采用两阶段机制：
  1. Agent 从简略清单中选择工具。
  2. 系统仅在此时注入该工具的完整 JSON Schema。
- 记录每一项子任务的 Token 消耗，实时展示在 UI 面板上。

## 4. 第四阶段：质量堡垒 (对抗性审查与神经符号验证)

**目标：** 引入"黑客/审查员"角色，解决 99% 到 100% 的"最后一公里"逻辑 Bug。

### 4.1 对抗性双智能体 (Red-Teaming Swarm)

- **模型 A (实现者):** 编写代码。
- **模型 B (黑客/资深架构师):** 独立运行，拥有不同的 System Prompt。尝试寻找 A 代码中的零日漏洞、逻辑漏洞或违反 Spec 的行为。

### 4.2 神经符号网关 (Z3 Solver 集成)

- 从 SDD 规范中提取逻辑断言，由 SMT 求解器进行数学验证。只有"证明安全"的代码才允许合并。
- 对于关键系统，引入 **"带证明的代码（Proof-Carrying Code）"**。Agent 不仅提交代码，还要提交证明该代码符合安全属性的逻辑断言。

### 4.3 规范驱动的 TDD 闭环

四阶段工作流规范：

1. **Specify（规范化）：** 将模糊语意转化为可测试的 `success_criteria` 标签。
2. **Plan（架构规划）：** 生成技术路线图，强制校验组件复用性。
3. **Tasks（微任务化）：** 分解为独立的、可运行的微任务（如"创建 email 验证端点"）。
4. **Implement（实现与验证）：** Agent 必须自主编写测试用例并运行，只有在 **Test Green** 状态下才允许合并。

## 5. 第五阶段：控制平面 (可干预任务图 UI)

**目标：** 终结 AI 运行的"黑盒"状态，让执行过程透明、可编辑。

### 5.1 可视化任务 DAG

- 侧边栏显示任务节点图（有向无环图），清晰标注每个节点所分配的模型、预计成本及当前状态。
- 每个节点代表一个原子任务（如"修改数据库 Schema"、"更新 API 定义"）。

### 5.2 在线转向机制 (Intervenable Steering)

- **计划确认（Plan Approval）：** Agent 在执行前生成详细实施计划，用户可直接在图中编辑计划路径。
- **状态检查点（Git Checkpoints）：** 每一轮代码修改自动创建 Git 暂存区检查点，支持一键对比与回滚（Rollback）。
- **暂停与干预：** 运行过程中允许用户点击"暂停"，修改 Agent 的中间变量或文件状态，然后恢复运行。

### 5.3 开发者交互界面 (UI/UX)

- **Artifacts 视图：** 在代码编辑器旁提供实时渲染的预览窗口（用于 UI 代码）和任务列表状态视图（用于后端逻辑）。
- **三模式切换：**
  - **Vibe Mode：** 用于快速探索和草图绘制。
  - **Flow/Agent Mode：** 用于自主执行长时程任务。
  - **Spec Mode：** 锁定架构约束，进入严密的生产环境编码模式。
- **成本仪表盘：** 实时展示各层级模型的 Token 消耗、缓存命中率、任务成本趋势图。

## 6. 系统级开发指令 (System Prompt)

> "你现在的身份是 Sentinel-IDE 的首席架构师。我们在构建一款高度智能且具备成本意识的 AI 原生编辑器。
>
> - **代码开发规范：** 底层涉及静态分析和索引的模块使用 Rust，并提供 FFI 接口；上层管理逻辑使用 Python。
> - **路由优先：** 请在每个 Agent 的工作流中设计『分发步』。根据任务特征自动选择 Haiku/Sonnet/Opus 等模型级别，严禁一律使用昂贵模型。
> - **对抗性设计：** 每一轮 Implement 之后必须由一个独立的、具有不同 System Prompt 的 Reviewer 代理进行对抗性扫描。
> - **成本追踪：** 实现 CSO (Context State Object) 压缩协议，记录每一项子任务的 Token 消耗，并实时展示在 UI 面板上。"

## 8. 预期改变：真正的自动化工厂

- **高效分工：** "搜索代码"这种琐事由几分钱的 Haiku 瞬时完成，"逻辑重写"这种重活由 Opus 细心雕琢，总成本降低 60%-80%。
- **质量托底：** 黑客模型会指出实现者漏掉的空指针检查，Z3 验证器会确保逻辑 100% 严密。
- **全程掌控：** 你在任务图上看着三个模型分工合作，就像指挥一个精简的高级开发团队。

通过这一套设计，Sentinel-IDE 将不再只是一个"带 AI 插件的编辑器"，而是一个真正的 **"人机协作软件制造工厂"**。
